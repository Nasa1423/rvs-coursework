# ATmega8: два точных расписания и команды USART

Основной вариант первой ачивки. Код полностью заменяет прежнюю очередь событий.

## Что именно означает точность

Измеряется **запись первого байта строки в UDR** — программное начало передачи
через USART. Для запланированного срока D проверяется `0 <= t_OUT_UDR - D <= 4`
в тактах CPU. Это не пауза в четыре такта между `ping` и `pong`.
Физический стартовый бит на TX зависит также от тактирования USART; точность
его фронта здесь не заявляется и на плате не измерялась. Слайд не определяет
точку измерения. Выбранная трактовка явно зафиксирована, а не согласована
с преподавателем. Если требование относится именно к фронту TX, эта проверка
его не закрывает.

## Устройство

- Реальная частота CPU 8 МГц; USART 500000 бод, 8N1, RX=PD0, TX=PD1.
- Timer1 непрерывный, без предделителя. OCR1A/OCR1B обслуживают два расписания.
- Обработчик просыпается за 512 тактов до срока. Перед сроком он опрашивает
  флаг сравнения циклом длиной четыре такта и записывает первый байт в UDR.
- Остаток строки отправляется с опросом готовности USART. Приём команд
  обслуживается в промежутках, в том числе внутри обработчика.
- Следующий срок = предыдущий срок + период. Задержки не накапливаются.
- Второе расписание запускается со сдвигом `PHASE=(L1+2)*160+2048`. Это явное
  решение проблемы совпадений; общий одновременный старт здесь не используется.
- После принятого изменения настроек оба расписания назначаются заново от
  текущего счётчика. Сам счётчик не останавливается и не обнуляется.

## Допустимые настройки и минимум

L1/L2 — длины полезного текста (0..16). CRLF добавляется автоматически.
При выбранных частоте и скорости один байт 8N1 занимает 160 тактов.
`C1=(L1+2)*160`, `C2=(L2+2)*160`, `G=2048`, `g=gcd(T1,T2)`.

Принимаются периоды 1..57344, удовлетворяющие **g >= C1+C2+2G**.
Это точный критерий принятия для реализованной политики резервирования,
а не поиск самого быстрого теоретически возможного передатчика.

Разности сроков двух периодических потоков образуют `PHASE + k*g`.
Следовательно, для двух направлений необходимо и достаточно
`PHASE >= C1+G` и `g-PHASE >= C2+G`. Выбор PHASE выше удовлетворяет обоим
неравенствам ровно при указанном критерии. Окна G оставлены для обслуживания
USART, раннего входа в обработчик и ответа на команду. Они не означают
остановку аппаратного таймера.

Каждый положительный период кратен g, поэтому
`T1+T2 >= 2g >= 2(C1+C2+2G)`.
Равенство достигается при `T1=T2=C1+C2+2G`.

Для **ping/pong**: C1=C2=960, T1=T2=6016, **минимальная сумма 12032 такта**.
При 8 МГц это 752 мкс на каждый период, сумма 1,504 мс; PHASE=3008 тактов.
Для пустых текстов (только CRLF): T1=T2=4736, сумма 9472 такта.
При сумме ниже этой границы программа не принимает конфигурацию. Резерв G
фиксирован: доказанный минимум относится именно к этой реализации.

## Команды

Одна ASCII-команда на строку, завершается LF. Следующая команда — после ответа
`!OK\r\n` или `!ERR\r\n`. Нельзя отправлять несколько команд без ожидания ответа.

| Команда | Действие |
|---|---|
| `T1 5DC0` | Период первого расписания 24000 тактов |
| `T2 3E80` | Период второго расписания 16000 тактов |
| `P 1780 1780` | Атомарно задать оба периода 6016 тактов |
| `S1 hello` | Изменить первый текст |
| `S2 world` | Изменить второй текст |
| `S1 ` | Пустой первый текст, остаётся CRLF |
| `R` | Перезапустить оба расписания с установленным сдвигом |

Периоды — ровно четыре шестнадцатеричные цифры. Тексты — до 16 печатных ASCII
символов, не начинаются с `!` (префикс ответов). Команда P позволяет перейти
между допустимыми парами без запрещённой промежуточной конфигурации.
Например, `P 177F 177F` с ping/pong возвращает !ERR и сохраняет прежние параметры.
НОД и проверка вычисляются при разрешённых прерываниях. Публикация параметров
короткая и атомарная; TCCR1B/TCNT1 при этом не изменяются. Ошибочные константы
при сборке также проверяются на старте: выдаётся !ERR, расписания не запускаются.

## Проверка

```sh
cd serial_scheduler
python3 build_and_check.py
```

Нужны Python 3, git, make и clang/cc. Скрипт скачивает зафиксированные версии
AVRA/simavr, собирает исходник и выполняет тесты на полученном HEX.
Результат: `build/command-tests/result.json`.
Последний сохранённый прогон: `checks/result.json`.

**337 сценариев, 38048 измеренных начал строк, отклонение 1..4 такта.**
Проверены команды, отказ без изменения параметров, перезапуск, граница
периодов, все 289 пар длин, разные фазы приёма на полной скорости, переполнение
счётчика, отсутствие пропусков в установившемся расписании, длительный расчёт
НОД без остановки счётчика. Прогон выполнен в симуляторе, не на плате.

В используемом simavr для ATmega8 есть ограничения модели UART: общий адрес
UBRRH/UCSRC и расчёт длительности кадра с лишним битом чётности. Стенд явно
задаёт `cycles_per_byte=160` по настройкам 8 МГц / 500 кбод / 8N1. Это единственная
поправка модели; выполнение инструкций, Timer1 и отметки OUT UDR не изменяются.
Стенд не моделирует физические фронты TX. Контроль регистра UDR не выдаётся
за измерение этих фронтов.

Подключение к реальной плате: общий GND, TX адаптера → PD0, RX адаптера → PD1;
логические уровни должны соответствовать питанию ATmega8. Необходима реальная
частота 8 МГц, а не только значение F_CPU в исходнике.

```sh
python3 -m pip install pyserial==3.5
python3 send_command.py --port /dev/cu.usbserial-... 'P 1780 1780'
```
