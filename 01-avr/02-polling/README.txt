Вариант 2: Опрос аппаратных флагов

Прерывания сравнения отключены. Основной цикл проверяет OCF1A/OCF1B,
переназначает сроки и кладёт сообщения в FIFO. Прерывание RX остаётся.
Опрос должен успевать переназначить сравнение до следующего срока;
добавление долгих операций в основной цикл требует новой проверки диапазона.

Управляемые таймеры ATmega8

Код: timers.asm. Сборка: timers.hex. Описание: report.pdf.
AVR Assembler для ATmega8, реальная частота CPU 8 МГц.
USART: 500000 бод, 8N1. RX=PD0, TX=PD1, общий GND.
Образ не предназначен для ATmega328P без адаптации. Fuse-биты не меняются.

Протокол команд
Одна строка ASCII с LF; CR игнорируется. Отправлять следующую команду
после ответа на предыдущую. Периоды задаются РОВНО четырьмя HEX-цифрами
в тактах CPU, а не в миллисекундах. Регистр hex-цифр не важен.

  T1 4000       период первого таймера = 0x4000 = 16384 такта
  T2 6000       период второго таймера = 0x6000 = 24576 тактов
  S1 hello      заменить текст первого сообщения
  S2 world      заменить текст второго сообщения
  S2            команда «S2 » с пробелом после 2: пустой текст
  R             перезапустить оба расписания от общего текущего момента
  ?             вывести периоды и длины строк

Текст: 0..16 печатных ASCII-символов; первый символ не может быть '!'.
Программа сама добавляет CRLF. Ответы начинаются !OK или !ERR и не
перемешиваются с периодическими строками. Пример ответа на ?:
  !OK T1=4000 T2=6000 L1=05 L2=05
Все числа в ответе записаны в HEX; L1/L2 не включают CRLF.

Ошибки:
  !ERR SYNTAX  неизвестная команда, неверный формат, длина или префикс
  !ERR INPUT   слишком длинная строка / ошибка приёма; повторить после LF
  !ERR LOAD    настройка вне поддерживаемого диапазона нагрузки
  !ERR QUEUE   очередь таймеров переполнена; PB0 остаётся включённым до R
При отклонении команды прежние параметры сохраняются.

Правило допуска для каждого таймера:
  period >= max(4096, (длина_текста + 2) * 1024), period <= 65535.
Это консервативный рабочий диапазон, а не точный алгоритм поиска всех
возможных конфигураций. Для ping/pong минимальный допускаемый период
равен 6144 (0x1800), сумма двух таких периодов = 12288 тактов.
Для 16 символов нужен период не меньше 18432 (0x4800).

Изменение периода не переносит уже назначенное ближайшее событие.
Новый интервал используется при назначении следующего срока при опросе флагов.
Для немедленного совместного начала нового расписания после T1/T2 вызвать R.
R не останавливает аппаратный счётчик: он переназначает сравнения и очищает
очередь старых событий. Тексты меняются между отправками целых сообщений.

Проверка команды и подготовка текста выполняются с разрешёнными прерываниями.
Короткие критические секции защищают публикацию 16-битного периода и
общий снимок счётчика при R; TCCR1B при этом не выключается.

Воспроизведение симуляции:
  python3 reproduce.py
Нужны Python 3, git, make, clang/cc и доступ к GitHub. Инструменты собираются
локально в build/. Проверяются собранный HEX, RX-команды, TX-ответы, память
параметров, непрерывность отсчёта и правильность строк. Плата не нужна.

Сборка отдельно установленным AVRA:
  avra -I /path/to/avra/includes -o timers.hex timers.asm

Управление реальной платой (пока не проверялось):
  python3 -m pip install -r requirements.txt
  python3 serial_console.py --port /dev/cu.usbserial-... '?'
  python3 serial_console.py --port /dev/cu.usbserial-... 'T1 4000'
Частота 8 МГц должна быть настроена на самой плате; F_CPU не настраивает кварц.

Точность
Счётчик и сравнения работают независимо от очереди USART. Один USART
передаёт сообщения последовательно, поэтому точность НАЧАЛА ПЕРЕДАЧИ
в пределах 4 тактов от совпадающих событий не обеспечивается. 4 такта
нельзя подменять точностью аппаратного compare. Минимум 12288 относится
только к выбранному правилу допуска, а не к глобальному пределу устройства.

В simavr UART_IRQ_OUTPUT означает запись UDR, а не наблюдение TX-пина.
В использованной ревизии есть упрощения расчёта скорости/длины символа;
тесты подтверждают логику программы, но не сертифицируют физические UART-тайминги.
