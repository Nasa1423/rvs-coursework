# Ачивки по распределённым вычислительным системам

Репозиторий содержит три реализации каждого из первых двух заданий.

**Ачивка 2 исправлена по уточнениям: PostgreSQL, ошибки в stdout, две UML-диаграммы,
HTTP POST и оба бизнес-правила. Ачивка 1 пока не закрывает среднюю и высокую
сложности: физический вывод в пределах четырёх тактов не обеспечен.**

### Запуск первого варианта

Нужны Python 3.12+ и установленный PostgreSQL (локально проверено с 17.6).

```sh
cd 02-client-server/01-row-lock/number_service
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 start.py --pg-bin /path/to/postgresql/bin
```

В другом терминале из того же каталога:

```sh
python3 request.py 5
python3 request.py 5
python3 request.py 4
python3 request.py 6
```

Результаты: `200/result=6`, `409/DUPLICATE_NUMBER`,
`409/PREDECESSOR_OF_PROCESSED`, `200/result=7`.
Оба бизнес-отказа появляются в **stdout** приложения вместе с `request_id`.
Запускатель наследует stdout; записи не скрываются в файле.
Проверка: `python3 verify.py --pg-bin /path/to/postgresql/bin`.

Для альтернативных вариантов используются `run_local.py`, `client.py` и
`test_integration.py` с теми же аргументами PostgreSQL. Инструкция есть внутри
каждого каталога. Каждому варианту нужна собственная база `.runtime`.

Вход: `POST /increment`, `Content-Type: application/json`, `{"number":5}`.
Допустимы целые числа 0..N; по умолчанию N=1000000. Ответ N+1 допустим.
История хранит и бизнес-отказы для корректного числа: повтор отказа — повтор.
В базе сохраняется вход n, а не ответ n+1; проверка повтора выполняется первой.

### Проверки

Локально прошли 10 / 11 / 11 интеграционных тестов по вариантам, включая
отдельную проверку обеих бизнес-ошибок в stdout и их отсутствия в stderr.

## Ачивка 1 — AVR Assembler / ATmega8

| Вариант | Исходники | Отчёт |
|---|---|---|
| FIFO и основной цикл | [Код](01-avr/01-queue/serial_scheduler) | [PDF](01-avr/01-queue/report.pdf) |
| Опрос флагов | [Код](01-avr/02-polling) | [PDF](01-avr/02-polling/report.pdf) |
| Счётчики и USART-прерывание | [Код](01-avr/03-interrupt) | [PDF](01-avr/03-interrupt/report.pdf) |

Сохраняются имена `TIMER1_INTERVAL`, `TIMER2_INTERVAL`, `TIMER1_STR`, `TIMER2_STR`.
Начальные строки — `ping\r\n` и `pong\r\n`. Реализованы команды периодов,
строк, перезапуска и проверки параметров без остановки аппаратного счётчика.
У каждого варианта прошёл 31 функциональный сценарий на собранном HEX в simavr.

**Ограничение:** проверка нагрузки консервативна, требуемый глобальный минимум
не найден. Физическая точность TX в четыре такта не обеспечена. Наличие команд
не означает выполнение высокой сложности, поскольку она включает среднюю.

`timing_audit.py` (в первом варианте — `checks/timing_audit.py`) даёт
аналитический контрпример для текущей модели: общий старт, целые строки,
один USART. При периодах 16000/24000 события совпадают на 48000-м такте;
начала двух строк должны быть разделены не менее чем 960 тактами, что больше
окна ±4 такта. Это вывод для данной модели, а не доказательство невозможности
любой трактовки задания. Требуется уточнение точки измерения и фаз запуска.

## Источники и статус

Условие взято из двух презентаций преподавателя и дополнено уточнениями:
результат второй ачивки — ссылка на Git, SQLite запрещён, лог — stdout,
язык можно любой. Техническая документация:
[ATmega8](https://ww1.microchip.com/downloads/en/DeviceDoc/Atmel-2486-8-bit-AVR-microcontroller-ATmega8_L_datasheet.pdf),
[PostgreSQL](https://www.postgresql.org/docs/17/explicit-locking.html),
[Python logging](https://docs.python.org/3.12/library/logging.html#logging.basicConfig).

Ачивка 3 — отдельная устная подготовка, здесь не реализована.
Сервисы предназначены для локальной демонстрации, без авторизации и TLS.

Уточнение пользователя: возможно, четыре такта относятся к промежутку между
выводами ping и pong. Это предположение, не подтверждённое преподавателем.
Промежуток между началами строк и пауза между концом одной строки и началом
другой — разные условия; ни одно здесь не выдано за выполненную точность.
