### Запуск первого варианта

Нужны Python 3.12+ и установленный PostgreSQL (локально проверено с 17.6).

```sh
cd 02-client-server/01-row-lock/number_service
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 start.py --pg-bin /path/to/postgresql/bin
```

В другом терминале из того же каталога:

```sh
python3 request.py 5
python3 request.py 5
python3 request.py 4
python3 request.py 6
```

Результаты: `200/result=6`, `409/DUPLICATE_NUMBER`,
`409/PREDECESSOR_OF_PROCESSED`, `200/result=7`.
Оба бизнес-отказа появляются в **stdout** приложения вместе с `request_id`.
Запускатель наследует stdout; записи не скрываются в файле.
Проверка: `python3 verify.py --pg-bin /path/to/postgresql/bin`.

Для альтернативных вариантов используются `run_local.py`, `client.py` и
`test_integration.py` с теми же аргументами PostgreSQL. Инструкция есть внутри
каждого каталога. Каждому варианту нужна собственная база `.runtime`.

Вход: `POST /increment`, `Content-Type: application/json`, `{"number":5}`.
Допустимы целые числа 0..N; по умолчанию N=1000000. Ответ N+1 допустим.
История хранит и бизнес-отказы для корректного числа: повтор отказа — повтор.
В базе сохраняется вход n, а не ответ n+1; проверка повтора выполняется первой.

### Проверки

Локально прошли 10 / 11 / 11 интеграционных тестов по вариантам, включая
отдельную проверку обеих бизнес-ошибок в stdout и их отсутствия в stderr.
Используются два приложения и два веб-сервера. Проверяются гонки, откат,
сохранение истории и сбои. Штатные запускатели проверены отдельно.
Результаты находятся в `verification.json` / `test_results.json` и
`launch_results.json`. Шаблон GitHub Actions сохранён в `checks/web-tests.workflow-example.yml`;
он не активирован: текущей авторизации GitHub не хватает права `workflow`.

## Ачивка 1 — AVR Assembler / ATmega8

Текущая основная реализация: **[01-deadline](01-avr/01-deadline)**.
[Полный исходник](01-avr/01-deadline/serial_scheduler/serial_scheduler.asm),
[отчёт](01-avr/01-deadline/report.pdf),
[результаты](01-avr/01-deadline/serial_scheduler/checks/result.json).

Вместо очереди — ранний вход в обработчик и четырёхтактное ожидание флага
Timer1 перед первым OUT UDR. Проверены 38048 начал строк: отклонение 1..4 такта.
Оба периода, оба текста и перезапуск доступны через USART. При расчёте НОД
счётчик продолжает работать, таймерные сообщения продолжают передаваться.
Недопустимые настройки отклоняются без изменения текущих параметров.

Для ping/pong минимальная принимаемая сумма периодов в реализованной политике
резервирования: **6016 + 6016 = 12032 такта**. Доказательство и формула для
других длин приведены в отчёте. Это минимум данной реализации с фиксированным
служебным резервом, не универсальный предел ATmega8.

Точка измерения явно определена как запись первого байта в UDR. Преподаватель
её не уточнял; физический стартовый бит TX и пауза между строками — другие
величины. Они не подменяются результатами этого теста. Проверки выполнены
в simavr с явно описанной поправкой длительности UART-кадра, не на плате.
Второе расписание запускается с рассчитанным сдвигом; общий одновременный
старт намеренно заменён фазовым расписанием.

Ранее сделанные [опрос флагов](01-avr/02-polling) и
[счётчики с USART-прерыванием](01-avr/03-interrupt) сохранены как сравнительные
примеры. Они не получили новую гарантию точности и не являются текущим
решением требования четырёх тактов.
